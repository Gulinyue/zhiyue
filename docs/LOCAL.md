# 本地独立分支说明

## 分支与基线

项目最初没有自己的 Git 目录，而是落在 D 盘根部的空仓库中。本次为 `climb-src` 建立独立仓库，先在 `codex/cloud-recovered` 提交恢复版基线，再分支出 `codex/local-standalone`。未修改 D 盘根仓库，也未推送任何远端。

该分支只重建客户端能独立承担的功能，不模拟原订阅和账号服务。旧服务器上的账号、付费记录和内容已经不可恢复。

## 运行路径

```text
本地工作台
  → 主进程 IPC 权限校验与参数校验
  → 读取操作系统加密的用户模型 Key
  → 用户配置的模型接口（可为本机模型服务）
  → SSE 流式结果返回界面
  → 保存文字会话到本机
```

没有旧 Climb 登录、套餐刷新、用量心跳、自有模型 entitlement、旧版本检测、远控重连或 ASR WebSocket。用户可主动通过官方 OAuth 授权自己的 ChatGPT 账号；与原 Climb 账号服务无关。旧云端模块保留在源码中供对照，构建仅引用 `src/renderer/local/app.mjs` 及其依赖。生成的主进程和界面包不含旧 Climb 后端域名。

旧记录桥仍需要一个稳定的所有者字段，因此使用固定本机命名空间 `local@climb.local`。它不用于网络鉴权，没有访问令牌，也没有伪造订阅或配额。

## 本机存储

- `local-workspace.json`：最多 100 份会话，每份最多 200 条文字消息，总量上限 32 MiB。消息不保存 API Key 或原始截图。满额时明确报错，不自动删旧记录。
- `knowledge-libraries-v3/`：最多 10 份本机文本资料，可勾选是否参与匹配。界面单份文本限制 10 万字符，TXT / Markdown 导入限 400 KB。
- `personal-model-credentials.json`：操作系统加密的模型 Key；加密不可用时拒绝持久化。
- `personal-model-profiles.json`：模型连接元数据，文字和截图两个用途分别配置。
- `records-v1/`：可选截图归档，沿用原容量与安全路径检查。

普通开发启动使用 `.runtime/local-dev/`。原恢复版数据保留在原位置，未自动迁移或删除。

本机无认证模型使用内部占位凭据满足兼容适配器格式要求；不需要用户提供真实 Key。启用认证的本机服务应填写其实际 Key。

## 知识库与上下文

界面按关键词匹配中英文文本块，选取相关片段；没有嵌入或向量服务依赖。最近 30 条文字消息经过长度限制后作为上下文；历史截图不重新发送。资料中的文字作为参考数据处理。

## 验证结果与边界

41 项单元测试覆盖原截图通道、超时资源释放、模型流、取消、本机资料与记录，以及新增的无 entitlement 请求、模型选择、关键词检索和会话结构。

本地 Electron 冒烟测试通过真实界面保存模型配置、资料并发送提问，使用本机 HTTP 模拟模型返回 SSE，验证图片路由、停止请求、保存与重开会话、截图并发送快捷键、专注窗口令牌和浮层读取权限。所有其他网络请求被阻断；报告中的非预期网络请求为零。

尚未验收用户真实模型服务、真实桌面连续截图、macOS、会议共享或录屏兼容性。语音识别、手机远控、云端职位发现和原云端的结构化演练流程未接入；文字模拟面试只是用户模型上的对话功能。

## 回到恢复版

保存本地分支修改后可以切换 `codex/cloud-recovered` 并重新构建。该基线仍包含原云端调用，只用于代码对照或将来迁移自建后端。它不会恢复已经清除的服务器数据。


后续增加多服务商四协议接入、官方 ChatGPT OAuth、模型发现，以及悬浮窗透明度、移动、滚动、隐藏和恢复快捷键，详见 [模型接入与窗口操作](MODELS-WINDOW.md)。ChatGPT 令牌保存到操作系统加密的 `chatgpt-authorization.json`，不进入本机会话文件。
